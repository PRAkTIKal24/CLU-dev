## 0. The answer

**The w16 CMAZE-T store win does NOT survive symmetric inputs.** No condition wins by the
pre-registered rule.

| condition (every arm gets the identical input) | VAL verdict | scored runs | TEST verdict | what it says |
|---|---|---|---|---|
| **WORDS-MAIN** (27 main one-hots; CLU = learned blind-sequential reading) | **LOSS** (VB1, VB2 fail) | 0 | — | rivals given the words compose far better than a main-effects CLU: 0.747 vs 0.334 |
| **WORDS-FULL** (the 318-wide design to CLU and every rival) | **LOSS** (VB1 fails) | 0 | — | ⭐ **the pair block, not the store, carries the w16 margin**: a matched transformer given the CLU's own design reads 0.742 vs CLU 0.725 |
| **OBS** (conv-AE features ⊕ dynamics ⊕ action; CLU through a declared extractor) | **LOSS** (VB1, VB4 fail) | 0 | — | CLU 0.351 vs rivals 0.457; the extractor recovers the whole word tuple on only 6–22 % of held-out n-way rows |
| **BOTH** (words + observation, every arm) | PASS (knife-edge) | **3** (1–3/9) | **LOSS** (SB1 fails) | margin +0.099 < 0.10, and the CLU is behind the matched 8k LSTM on seed 1 (0.566 vs 0.567) |
| *OBS-X10 (diagnostic, AMENDMENT 1; never a bar)* | *would read LOSS* | 0 | — | even a 10× extractor leaves the CLU at 0.447 vs rivals 0.461 |

**Budget: 3 of 9 scored runs spent (BOTH, TEST), 6 DECLARED NOT-RUN** (§6).

In short: w16's rivals read a 636-dim conv-feature observation, while the CLU read the five
words through a 318-wide `[bias|main|pair]` design. Give the rivals the same input and the
margin goes away. With identical words (WORDS-FULL) matched rivals tie or beat the CLU. With
main effects only (WORDS-MAIN) the rivals win by +0.41. With the observation only (OBS) the
CLU loses, because its request must first be read from that observation. The one condition
that cleared VAL (BOTH) had a +0.108 margin. That margin rests on the matched-float rule:
954 input dims leave the rivals a 4-unit hidden layer. It failed on TEST (+0.099, and behind
on seed 1). ⭐ **What survives is the store GATE, not a rival margin.** On every condition the
four charter-C controls collapse relative to the CLU (landscape_removed = 0.000
everywhere). Exact store-scoped deletion also holds (§5). So the store is load-bearing for
the CLU's own read, but on this task it is not better than a matched network given the same
input.

## 1. Method (as run)

* Store config **A1 (latent 128, K 2, 6 atoms, ridge 1.0) UNCHANGED**; engine, banks
  (VAL base+200k.., TEST base+300k..), hold-outs, codec recipe, controls, blind arms, floors,
  rival recipe imported from w15/w16 unmodified. **Instrument-unchanged check:** WORDS-FULL
  and BOTH's CLU on VAL n-way = 0.8019 / 0.5689 / 0.8034, and BOTH's CLU + all four controls
  on TEST n-way = 0.800 / 0.566 / 0.808 (controls 0.000 / 0.225 / 0.244 / 0.166). Both
  triples match w16 A1 to every printed digit (`w16-maze-wm/t1/A1_*`). Only the rivals'
  input changed.
* **`landscape_shuffled_across_wells` is a DERANGEMENT, asserted and printed:** `[1, 0]` on
  every seed of every run (K = 2; `across_wells_derangement` in every JSON; the runner
  asserts no fixed point).
* **Rivals:** mlp / lstm / transformer (+ cont_mlp in WORDS-*; + an "obs ⊕ extractor
  one-hots" copy of each in OBS), matched on read-path floats (residuals −2 % … +6 %,
  TABLES §4). Each is trained at **8,000 steps** (the row) and **80,000 steps** (the 10×
  column). R\* for VB1/SB1 = the best matched rival over **both budgets** and every
  kind/variant. A 10×-read-floats column (8,000 steps) is printed and is never a bar.
* **Bars** (PREREG), on unseen n-way (`exact`), means over 3 seeds:
  * VB1/SB1: CLU ≥ R\* + 0.10 AND CLU > R\* on every seed.
  * VB2/SB2: every control ≤ CLU − 0.15.
  * VB3/SB3: learned blind max ≤ CLU − 0.05 (WORDS-MAIN: BLIND-COLOUR only, since the CLU
    IS BLIND-SEQUENTIAL there).
  * VB4/SB4: WORDS lookup ≤ CLU − 0.10.
* **Declared choices** (LOG.md C1–C7):
  * In OBS the extractor's 21,275 floats are added to the matched target (25,859).
  * In OBS the CLU is fitted and read on extracted words.
  * The state encoder is trained only where an arm consumes the observation.
  * Deletion runs on every scored TEST run.
* ⚠ Measured: the w9 observation's dynamics block is 31 wide at k = 4 (`dyn_dim(4)`); the
  "29" in the brief and the w9 docstring is stale. The observation is used unchanged (636 = 600 + 31 + 5).

## 8. What would have proved the w16 win input-independent — and what happened
* WORDS-FULL: matched rivals given the CLU's exact design staying ≥ 0.10 below the CLU. **They
  did not** (transformer 0.742 vs 0.725). The pair block carries the margin.
* OBS: the CLU keeping its margin once its request must be read from the rivals'
  observation. **It did not** (0.351 vs 0.457).
* BOTH: a margin ≥ 0.10 on TEST, ahead on every seed. **It did not** (+0.099; behind on seed 1).

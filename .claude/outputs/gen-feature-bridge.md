## 6. ⭐ POST-HOC control (NOT pre-registered): the B drop is mostly PHOTOMETRIC, not compositional

The Montero cell is `all three hues ≥ 0.8 ∧ scale ≥ 1.1 ∧ shape = cylinder ∧ orientation > 20`. **All three hues ≥ 0.8 puts floor, wall and object in the same magenta band**, so object/background contrast in B is near-minimal (visible in `runs/shapes3d_recon/seed_0/ceiling_grid.png`). A "held-out combination" explanation of the drop is therefore **confounded with a photometric one**.

Control (seed 0, `recon`, from the saved artifacts + the full-grid cache): `A_matched` = the **same photometric corner** with `shape ≠ cylinder`, minus any row used in fitting ⇒ **n = 209** seen combinations, never fitted, never held out.

| | n | aggregate | scale | shape | orientation | hues |
|---|---|---|---|---|---|---|
| `A_random` (the reported ceiling_A) | 1024 | 0.9476 | 0.859 | 0.904 | 0.924 | ≈1.000 |
| **`A_matched`** (same hues, seen shape) | 209 | **0.9203** | **0.703** | 0.876 | 0.943 | 1.000 |
| `B` (held out) | 72 | 0.8681 | **0.708** | **0.500** | 1.000 | 1.000 |

⭐ **`scale` on B (0.708) is statistically indistinguishable from `scale` on the photometrically matched *seen* set (0.703).** The scale loss is a **low-contrast rendering artefact of the hue corner, not a composition failure.** The only genuinely compositional term is **`shape`: 0.876 → 0.500**, i.e. the decoder does not reliably render the identity of a *large cylinder* it has never rendered.
Ratio against the matched control: **B / A_matched = 0.943** (vs 0.916 against random A) — i.e. the gate would pass **more** comfortably on the stricter control.

### ⭐ "ONE decoder, shared by every arm, forever" — what that means operationally, and how it is enforced
1. **One decoder per seed**, shared by all four arms at that seed. The bridge is **arm-independent by construction**: every draw is threaded from `--seed` alone and `--arm` is recorded as metadata only.
2. **Verified empirically, not asserted:** running `--stage encoder --seed 0 --arm clu` and `--arm lace` produced a **byte-identical** `encoder.pkl` (both sha256 `97dd3871521e689d…`) and an identical feature-cache checksum (`2a24a73782f3375f…`).
3. **Downstream guard:** `chlu.core.gen_bridge.assert_decoder_hash(decoder, expected)` raises `"…this is NOT the shared frozen decoder…"`. ⛔ Every arm calls it against `shared_decoder_hash.json` before scoring anything. `tests/…::test_assert_decoder_hash_catches_a_retrained_decoder` proves it fires.
4. Cross-checks that run at load time: the encoder checkpoint's hash must match its own manifest, and the feature cache's `encoder_param_hash` must match the loaded encoder, or the decoder stage refuses to start.

### ⭐ `D`, `N`, and the LACE whitening ruling (folded-in constraint)

| | value |
|---|---|
| penultimate feature shape | **(128, 4, 4)** |
| **`D = C·H·W`** | **2,048** (limit ~2e4) |
| `N` (train features fitted) | 8,192 · `N` (cached, full scope) = 480,000 |
| `shrinkage_mandatory` (`D > N`) | **False** (2,048 < 8,192) — shrinkage remains advisable, not forced |
| full `D × D` whitening feasible | **True** |
| **Option taken (Head ruling: our choices never weaken a competitor)** | **Option 1 — the feature width is chosen so LACE whitens NATIVELY** over a full `D × D` shrinkage covariance. ⛔ LACE is **not** pushed onto channel-only whitening, and needs **no** PCA projection. |

Recorded in every `encoder_manifest.json` / `bridge_manifest.json` under `whitening.lace_option`. ⛔ I did **not** silently pick a narrow encoder for our own convenience: 2,048 is a *2×2×2×2*-downsampled 4×4 map that reconstructs Shapes3D to MSE 0.0026–0.0031 (§8), i.e. the width is set by rendering quality and lands inside LACE's constraint, not the other way round.

## 14. Open questions / follow-ups / risks

1. ⚠ **No GPU run exists.** The ≤30 min/GPU budget is an *estimate* (§9). If the Hub needs it measured, the runs must be submitted by someone with cluster reachability.
2. **`shape` on B is 0.59 (0.50 at seed 0).** That is the one genuinely compositional deficit and it is *inside* the passing gate. Any arm's B-composition score is bounded by it — which is precisely what R3.2 says to normalise by, but see reconciliation item 2 for *which* normaliser.
3. **`ceiling_A` is measured on rows drawn from the same split, held back from every fitting stage.** On Shapes3D each grid cell is exactly one image, so a "seen combination, unseen image" set cannot exist in the literal sense; the honest A-equivalent is *unseen images of combinations the model was free to see*, which is what `select_rows` builds (8,192 fitted of 479,928 available). ⛔ This means A is **not** memorisation-inflated — but it also means A is not "training data" either, and the Hub should not later describe it as such.
4. **`n_train = 8,192` of 479,928.** A laptop-RAM decision (float32 images at 64×64×3 are 48 KB each). On a GPU it can be raised via `--n-train`; the ceiling would go up on both A and B and the ratio is the reported quantity, not the level.
5. **dSprites is wired but unmeasured.** `--dataset dsprites` runs (1-channel path is implemented and unit-tested), but per R6 the A/B/C cell is Shapes3D only, so no dSprites ceiling was produced.
6. The `cls` diagnostic decoder MSE is ~1.5× the `recon` one (0.0046 vs 0.0031), as expected for a classification pretext, and its `ceiling_A` is correspondingly lower — the diagnostic behaves the way fault-isolation needs it to.

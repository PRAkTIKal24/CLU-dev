## 8. Standing rules that cost this program passes to learn

1. ⛔⛔ **When the Head bounds a pass as minor or small, present the itemized worklist for line-item approval BEFORE any spoke launches.** A bounded instruction bounds *volume*, not just edit mode. (Add.60a — an over-scoped restoration cost a full pass and was reverted.)
2. ⛔ **A task file's factual premises are claims. Grep them before you write them.** An unverified premise is an instruction to hallucinate; three times only a spoke's refusal caught it.
3. ⛔ **A provenance fact has a shelf life.** *"X generates Y"* decays the moment the next pass touches Y — re-verify against the shipped artifact at the moment of use.
4. ⛔ **A task file is read ONCE, at boot.** Amending it after launch reaches nobody. A post-launch change needs a **message to the running spoke** — and the file edit should still be made so record and instruction agree.
5. ⛔ **Positive-control every negative.** This program has repeatedly had to defeat a false negative from a broken instrument. ⚠ **Standing grep hazard: directory-level grep over `.claude/` silently returns nothing** (it is gitignored) — sweep per-file.
6. ⛔ **Never diff against a file whose timestamp precedes the Head's last edit.**
7. ⛔ **Snapshot an accepted state off the live path AT ACCEPTANCE — the bytes, not just the hash.** A hash proves identity; it does not restore state.
8. ⛔ **One source, one build target.** The Head edits the canonical file; a pass edits the build copy; the Advisor reconciles. ⛔ No spoke writes to a file the Head is editing.
9. **Agent toolsets:** Bash-capable = `paper-referee`, `results-analyst`, `experiment-engineer`, `general-purpose`. ⛔ NOT `doc-curator`, `paper-writer`, `web-scout` — never assign them an execution step.
10. ⛔ **A byte-untouched acceptance criterion may never name a directory another in-flight spoke writes to.**
11. **Every task file carries a DIAL DECLARATION.**
